## Purpose

ユーザーの Google アカウントを OAuth で連携し、CalendarRabbit 専用の Google カレンダーへ DB 上のイベントを一方向（CalendarRabbit → Google）でミラー同期する。単一ユーザー・単一カレンダーをスコープとする。

## ADDED Requirements

### Requirement: Google アカウントの OAuth 連携

システムは Google の OAuth 2.0 ユーザー同意フローにより、ユーザーの Google アカウントを連携できなければならない（SHALL）。連携時に取得した refresh token を含む連携状態を永続化し、以後はユーザーの再同意なしにバックグラウンドで Google Calendar API を呼び出せなければならない（SHALL）。要求するスコープは Google Calendar のイベント読み書きに必要な最小限としなければならない（SHALL）。永続化する refresh token は保存時に暗号化しなければならず（SHALL）、平文で保存してはならない（MUST NOT）。

#### Scenario: refresh token は暗号化して保存する

- **WHEN** 連携完了により refresh token を永続化する
- **THEN** システムは refresh token を暗号化した状態で保存し、平文では保存しない

#### Scenario: 連携を開始する

- **WHEN** 未連携のユーザーが連携開始を要求する
- **THEN** システムは Google の同意画面へのリダイレクト先（認可URL）を返す

#### Scenario: 同意後のコールバックで連携を完了する

- **WHEN** ユーザーが Google 上で同意し、システムが有効な認可コードを受け取る
- **THEN** システムは認可コードをトークンに交換し、refresh token を含む連携状態を永続化して連携を有効にする

#### Scenario: 同意を拒否またはコールバックが失敗する

- **WHEN** ユーザーが同意を拒否する、または認可コードの交換に失敗する
- **THEN** システムは連携を有効にせず、連携状態を未連携のまま保ちエラーを通知する

### Requirement: 専用カレンダーの作成と識別

システムは連携完了時に、Google 上へ CalendarRabbit 専用のカレンダー（名称「CalendarRabbit」）を作成し、その calendarId を永続化しなければならない（SHALL）。以後の同期対象はこの専用カレンダーに限定し、ユーザーの他のカレンダーには書き込んではならない（MUST NOT）。既に専用カレンダーの calendarId を保持している場合は重複作成してはならない（MUST NOT）。

#### Scenario: 連携時に専用カレンダーを作成する

- **WHEN** 連携が完了し、まだ専用カレンダーの calendarId を保持していない
- **THEN** システムは専用カレンダーを1つ作成し、その calendarId を永続化する

#### Scenario: 既存の専用カレンダーを再利用する

- **WHEN** 既に専用カレンダーの calendarId を保持した状態で同期が発生する
- **THEN** システムは新たなカレンダーを作成せず、保持済みの専用カレンダーへ同期する

### Requirement: 初回連携時の既存イベントのバックフィル

システムは連携完了時に、DB に既に存在するすべてのイベントを専用カレンダーへ作成し、各イベントと生成された Google イベントIDの対応（マッピング）を永続化しなければならない（SHALL）。

#### Scenario: 既存イベントを専用カレンダーへ作成する

- **WHEN** 連携完了時に DB へ複数のイベントが既に存在する
- **THEN** システムは各イベントを専用カレンダーへ作成し、イベントごとに Google イベントIDのマッピングを永続化する

#### Scenario: 既存イベントが無い状態での連携

- **WHEN** 連携完了時に DB へイベントが1件も存在しない
- **THEN** システムはバックフィルとして何も作成せず、連携を有効にする

### Requirement: DB イベントの一方向ミラー同期

システムは Google 連携が有効な場合、DB 上のイベントの作成・更新・削除を専用カレンダー上の対応イベントへ即時に反映しなければならない（SHALL）。同期は一方向（CalendarRabbit → Google）であり、Google 側で直接行われた変更を DB に取り込んではならない（MUST NOT）。同期は日時・タイムゾーン・終日フラグを含むイベント内容を正しく反映しなければならない（SHALL）。

#### Scenario: 作成を同期する

- **WHEN** 連携が有効な状態で新規イベントが DB に作成される
- **THEN** システムは専用カレンダーへ対応イベントを作成し、Google イベントIDのマッピングを永続化する

#### Scenario: 更新を同期する

- **WHEN** 連携が有効な状態で既存イベントが更新され、そのイベントの Google イベントIDマッピングが存在する
- **THEN** システムは専用カレンダー上の対応イベントを更新後の内容へ反映する

#### Scenario: 削除を同期する

- **WHEN** 連携が有効な状態で既存イベントが削除され、そのイベントの Google イベントIDマッピングが存在する
- **THEN** システムは専用カレンダー上の対応イベントを削除し、マッピングを破棄する

#### Scenario: 未連携時は同期しない

- **WHEN** Google 連携が無効な状態でイベントの作成・更新・削除が行われる
- **THEN** システムは Google Calendar API を呼び出さず、DB 操作のみで完結する

### Requirement: 同期失敗時の耐性

システムは Google への同期が失敗しても DB 操作（作成・更新・削除）を成功として完了させなければならない（SHALL）。DB を正とするため、失敗した同期は未同期として記録し、後続の同期契機（対象イベントの再操作、または再送）で解消できなければならない（SHALL）。

#### Scenario: 同期失敗時も DB 操作は成功する

- **WHEN** イベントの DB 操作は成功したが Google Calendar API 呼び出しが失敗する
- **THEN** システムは DB 操作を成功として返し、当該イベントを未同期として記録する

#### Scenario: 未同期イベントを後続で再送する

- **WHEN** 未同期として記録されたイベントに対して次の同期契機が発生する
- **THEN** システムは専用カレンダーへ再度反映を試み、成功すれば未同期状態を解消する

### Requirement: 連携状態の取得と連携解除

システムは現在の Google 連携状態（連携済みか否か）を取得できなければならない（SHALL）。またユーザーは連携を解除でき、解除時に保存済みのトークン・calendarId・イベントマッピングを破棄しなければならない（SHALL）。連携解除時に Google 上の専用カレンダーを削除するか残すかをユーザーが選択できなければならず（SHALL）、いずれの場合もローカルの連携状態は破棄しなければならない（SHALL）。連携解除後はミラー同期を行ってはならない（MUST NOT）。

#### Scenario: 連携状態を取得する

- **WHEN** クライアントが連携状態の取得を要求する
- **THEN** システムは連携済みか未連携かを返す

#### Scenario: カレンダーを残して連携を解除する

- **WHEN** 連携済みのユーザーが専用カレンダーを残す指定で連携解除を要求する
- **THEN** システムは保存済みのトークン・calendarId・イベントマッピングを破棄して未連携にし、Google 上の専用カレンダーは削除しない

#### Scenario: カレンダーごと削除して連携を解除する

- **WHEN** 連携済みのユーザーが専用カレンダーの削除を指定して連携解除を要求する
- **THEN** システムは Google 上の専用カレンダーを削除し、保存済みのトークン・calendarId・イベントマッピングを破棄して未連携にする

#### Scenario: 連携解除後は同期しない

- **WHEN** 連携解除後にイベントの作成・更新・削除が行われる
- **THEN** システムは Google Calendar API を呼び出さず、DB 操作のみで完結する

### Requirement: 未同期イベントの手動再同期

システムは未同期（sync_pending）のイベントをユーザー操作で一括再送する手段を提供しなければならない（SHALL）。再送に成功したイベントは未同期状態を解消しなければならない（SHALL）。

#### Scenario: 未同期イベントを手動で再同期する

- **WHEN** 未同期イベントが存在する状態でユーザーが手動再同期を要求する
- **THEN** システムは未同期イベントを専用カレンダーへ再送し、成功したイベントの未同期状態を解消する

#### Scenario: 未同期イベントが無い状態での手動再同期

- **WHEN** 未同期イベントが1件も無い状態でユーザーが手動再同期を要求する
- **THEN** システムは何も再送せず、正常に完了する
