## Why

MVP をモバイルで実際に使うと、チャットとカレンダーの UX に複数の実害がある。送信したメッセージが応答が返るまで画面に出ない、会話をリセットできず履歴が際限なく肥大化する、月表示のカレンダーがモバイルで見切れる、下部タブがブラウザのナビゲーションバーと重なるなど、日常利用を妨げる問題が積み残っている。これらをまとめて解消し、モバイルでの実用性を高める。

## What Changes

- **チャット: 送信メッセージの即時表示** — ユーザーのメッセージを送信直後にローカルへ楽観的に表示し、アシスタント応答（web 検索を伴う長い待ち時間）を待たずに会話へ反映する。
- **チャット: 会話クリアと履歴上限** — 会話スレッドを全消去する「クリア」操作を追加する。あわせて Claude へ送る会話履歴を直近 N ターンに制限し、会話が伸びてもコンテキスト（トークン）が際限なく増えないようにする。
- **カレンダー: モバイルでの見切れ修正** — 月表示で「今日」等のナビゲーション後にカレンダーが見切れる不具合を修正し、どの遷移でも正しく描画されるようにする。
- **カレンダー: ナビゲーションラベル変更** — 「前」「次」ボタンのラベルを「<」「>」にする。
- **アプリ初期表示とタブ順序の変更** — 起動時の既定画面をチャットからカレンダーに変更し、下部タブの並びをカレンダー→チャット→設定にする。
- **カレンダー: 一覧表示のモバイル対応** — 表（テーブル）形式で改行されて見づらい一覧表示を、モバイルで読みやすいカード/リスト形式にする。
- **モバイル: 下部タブとナビゲーションバーの重なり回避** — セーフエリア（`env(safe-area-inset-bottom)`）を考慮し、下部タブが端末のナビゲーションバーと被らないようにする。
- **カレンダー: 予定タップ時の詳細→編集フロー** — 予定タップで直接編集フォームを開くのではなく、まず読み取り専用の詳細表示を出し、そこの「編集」ボタンから編集画面へ遷移する。

## Capabilities

### New Capabilities
（なし）

### Modified Capabilities
- `pwa-web-app`: 初期表示画面を「カレンダー」に変更し、タブ順序を規定。チャット画面に送信メッセージの即時表示と会話クリア操作を追加。カレンダー画面のモバイル描画（見切れ回避・一覧の可読性・セーフエリア考慮）と、予定選択時の「詳細表示→編集」二段フローを要件化。
- `chat-scheduling`: 会話スレッドのクリア（全メッセージ・予定案の削除）を追加。Claude へ渡す会話履歴を直近一定件数に制限する要件を追加。

## Impact

- **フロントエンド**: `frontend/src/App.tsx`（既定タブ）、`frontend/src/components/BottomTabs.tsx`（順序）、`frontend/src/screens/ChatScreen.tsx`（即時表示・クリア）、`frontend/src/screens/CalendarScreen.tsx`（見切れ・ラベル・一覧・詳細→編集）、新規の予定詳細表示コンポーネント、`frontend/src/styles.css`（セーフエリア・一覧カード・カレンダー高さ）、`frontend/src/api/client.ts` / `types.ts`（クリア API）。
- **バックエンド**: 会話クリア用エンドポイント（会話スレッドとひも付く message / event_proposal の削除）を `backend/internal/handler/chat.go` 系と usecase/persistence に追加。`backend/internal/usecase/chat/send.go` の `buildHistory` を直近 N ターンに制限。
- **仕様**: `pwa-web-app`、`chat-scheduling` の delta スペックを追加。
- **非対象**: `calendar-management`（バックエンドのイベント CRUD）と `app-settings` は変更しない。UI の全面刷新（memo2 の「モダン化」）は本 change のスコープ外。
